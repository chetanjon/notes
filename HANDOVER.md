# Where this is, and how to pick it up

Written so the work can carry on from a terminal with nothing else to hand.
`README.md` says what the app does; `NOTES_APP_SPEC.md` is the spec and wins
on any question of behaviour; `CLAUDE.md` is the rules. This file is the
state of play and the daily loop.

## What to open

Open the **folder** `~/notes` in the editor. That is the repository: git,
`project.yml`, the Swift sources, the docs, the store copy. Everything typed
into a terminal happens here.

Open `Notes.xcodeproj` in **Xcode** to build and run. It is generated by
`xcodegen generate` from `project.yml` and is not in git, so it may not exist
after a fresh clone; generate it and it appears. Never edit it, never commit
it, and never add a file to the project from inside Xcode: add the file to
the folder and regenerate.

Xcode is only needed to build, run and archive. Reading, editing, testing the
pure logic, git and the store copy are all fine from the terminal.

## The daily loop

```bash
cd ~/notes
git checkout main && git pull        # start from what is merged
xcodegen generate                    # rewrites Notes.xcodeproj, both plists, both entitlements
open Notes.xcodeproj                 # scheme Notes, pick the phone, Run
```

Tests, either `⌘U` in Xcode or:

```bash
xcodebuild test -project Notes.xcodeproj -scheme Notes \
  -destination 'platform=iOS Simulator,name=iPhone 16'
```

A change goes on its own branch, never on `main`:

```bash
git checkout -b fix/what-it-is
# edit, then run the tests
git commit -am "What changed and why"
git push -u origin fix/what-it-is
# open a pull request; merge it only when CI is green
```

CI runs the same tests on macOS for every push. It is the first place a
SwiftUI or SwiftData file is really compiled, so a green run is what makes a
change true, not a reading of the diff.

## Test on the phone before anything else

Delete the old app from the phone first: the bundle was renamed to **Matte**,
and Siri only learns the new name from a clean install.

Five things changed without ever being seen on a device, so start here:

1. Type a note, clear all of its text, leave. It should be **in the Trash**,
   not gone. (Clearing a note used to erase it outright.)
2. Pin a note and type in it for a minute. The Lock Screen card should keep
   up and not disappear.
3. Hold the pencil, dictate, tap Stop. The sheet must always let you out.
4. Delete a note whose notification is already showing in Notification
   Center. The notification should go with it.
5. A sparkle action that hangs should say "That took too long" rather than
   spin until you leave the note.

Then the ones carried over from the last round:

6. Tidy up on a line with a typo: `buy tomatos` should become
   `Buy tomatoes`, and three lines must stay three lines.
7. Reminders on `bread 2.20` (a price, not a time) and `rent on the 31st`
   (a real day in the next month that has one).
8. A checklist with an emoji in it, through Sort the list: the emoji must
   survive.
9. The Trash: a tap offers Put back or Delete; a swipe asks before deleting
   for good; Empty does not fire on a double tap.
10. Sort the list, ask-a-question search, the checklist over a selection, the
    edit time under the bar, the widgets in light and dark, the recall line
    and Move this there, and Siri under "in Matte".

Anything that fails becomes a `fix/*` branch, one pull request, the same as
the four rounds before it.

## Things learned the expensive way

- **The Linux tests only cover pure `String` logic.** Anything that imports
  SwiftUI, SwiftData, WidgetKit, ActivityKit, App Intents or Speech compiles
  first in Xcode or in CI. A fix to a view is a guess until it builds.
- **Reading a diff is not compiling it.** Twice, changes were made to
  "obvious" compile errors that were not errors; the build had already
  passed. Build first, then decide.
- **A guard on the model's output that is too strict turns the feature off
  in silence.** Tidy up rejected the very spelling fixes it exists to make,
  because the guard counted the original words and a corrected word is not
  the original word. Every guard needs a test with a real correction in it.
- **Whatever is derived and shown on the Lock Screen has to be reapplied.**
  That record is rebuilt from the note on every save and every foreground,
  so anything the model wrote is lost unless it is put back
  (`LockScreenSummary.cached`).
- **Anything shared with the widget must decode an older shape.** Swift's
  decoder throws on a missing key rather than taking a default, so a field
  added in a later version would blank the widget until the app was next
  opened. The hand-written `init(from:)` decoders exist for that, and any new
  field must follow the same pattern with a test.
- **Every write to a note goes through `NoteStore`**, or the Spotlight index,
  the widgets, the Lock Screen and the notifications drift apart.
- Match a regex against the text as written. Matching a lowercased copy and
  cutting those ranges out of the original crashed the app, because a letter
  can grow when it folds.
